Discord-бот на Python для регистрации участников на турниры faceit (без faceit API, требующего авторизацию бота). Формы реализуются штатными средствами Discord (Modals).

===========================================
СТЕК
===========================================
- Язык/библиотека: Python, discord.py (>=2.0 — поддерживает slash-команды и модалки из коробки, менять не нужно).
- БД: SQLite (слой доступа — на усмотрение реализации, например aiosqlite/sqlalchemy).
- Конфигурация: .env + python-dotenv. Переменные:
  - DISCORD_TOKEN — токен бота
  - GUILD_ID — айди гильдии (сервера)
  - SETUP_CHANNEL_ID — айди чата, где доступна команда настройки турнира (/tournament_active)
  - REGISTRATION_CHANNEL_ID — айди чата, где доступна регистрация (/tournament_join)
  - NOTIFICATION_CHANNEL_ID — айди чата, куда публикуется embed с данными заявки после подтверждения формы
  - MANAGER_ROLE_IDS — список айди ролей, которым разрешено создавать/редактировать турнир
  - PARTICIPANT_ROLE_ID — айди роли, которой разрешено принять участие в турнире
  - POST_TO_CHANNEL_ENABLED — true/false, включает/выключает публикацию embed в NOTIFICATION_CHANNEL_ID (на случай если уведомления не нужны)

===========================================
ПРАВА ДОСТУПА (двухуровневая защита)
===========================================
1. Проверка в коде: у вызвавшего пользователя должна быть одна из ролей из соответствующей env-переменной (MANAGER_ROLE_IDS для /tournament_active, PARTICIPANT_ROLE_ID для /tournament_join).
2. Ограничение на уровне самого Discord: команды дополнительно защищены стандартным правом Discord на использование конкретной slash-команды (настройка прав интеграции на сервере).

===========================================
КОМАНДЫ (ответы бота приватные/ephemeral)
===========================================

/tournament_active
- Доступна только в канале SETUP_CHANNEL_ID, только ролям из MANAGER_ROLE_IDS (+ право Discord).
- Параметры:
  - registration: true/false (обязательный) — включить или выключить регистрацию.
  - name: строка (опциональный) — название турнира. Если не указано при включении — используется последнее сохранённое название.
- Без даты проведения турнира, без ссылки/айди турнира — только вкл/выкл + название.
- При включении (registration=true):
  - Сохраняет/обновляет название турнира.
  - Открывает новый цикл регистрации. В рамках одного цикла (от включения до следующего выключения) каждый пользователь может заполнить форму только один раз.
- При выключении (registration=false):
  - Закрывает регистрацию, /tournament_join становится недоступна для участников.

/tournament_join
- Доступна только в канале REGISTRATION_CHANNEL_ID, только пользователям с ролью PARTICIPANT_ROLE_ID (+ право Discord).
- Если регистрация выключена — ответ: "На данный момент регистрация на турнир закрыта."
- Если пользователь уже подавал заявку в текущем цикле регистрации — ответ: "Вы уже отправляли заявку на регистрацию в этом турнире."
- Иначе показывает форму (Modal) с полями:
  - Ссылка на аккаунт faceit (обязательное, формат — должна начинаться с "https://")
  - Ссылка на аккаунт Steam (обязательное, формат — должна начинаться с "https://")
  - Комментарий (необязательное)
  - Учесть, что количество полей формы в будущем может измениться — структуру делать расширяемой, не хардкодить под ровно N полей.
- После отправки формы — кнопка "Подтвердить" с шаблонным текстом правил/условий турнира (текст зашит в коде, редактируется напрямую разработчиком, командного редактирования не требуется).
- После подтверждения:
  - Запись в БД: discord user id, ник, ссылка faceit, ссылка steam, комментарий, название турнира/id цикла регистрации, дата подачи заявки.
  - Если POST_TO_CHANNEL_ENABLED=true — отправка embed в NOTIFICATION_CHANNEL_ID с полями:
    - Ник в Discord (упоминание, @) — рядом айди в скобках "(...)"
    - Ссылка на faceit аккаунт
    - Ссылка на Steam аккаунт
    - Комментарий (если оставлен, иначе — пусто)

===========================================
ХРАНЕНИЕ ДАННЫХ ПО ЦИКЛАМ РЕГИСТРАЦИИ
===========================================
- Заявки не удаляются и не перезаписываются при новом включении/выключении регистрации — вся история хранится в БД.
- Каждая заявка привязывается к конкретному циклу регистрации (и к названию турнира, актуальному на момент подачи), чтобы можно было различать заявки разных турниров/циклов при просмотре БД напрямую.

===========================================
ПРОВЕРКИ ПРИ ЗАПУСКЕ СЕРВИСА
===========================================
При старте бота (до перехода в рабочий режим) выполнить самопроверку и падать/логировать понятную ошибку, если что-то не так:
1. Успешное подключение к Discord (login) и установление соединения с гильдией GUILD_ID (бот действительно состоит в этой гильдии).
2. Наличие всех прав (permissions/intents), необходимых боту для работы: отправка сообщений и embed'ов, использование slash-команд, чтение участников гильдии (для проверки ролей) — в каналах SETUP_CHANNEL_ID, REGISTRATION_CHANNEL_ID, NOTIFICATION_CHANNEL_ID.
3. Проверка, что все каналы из конфига (SETUP_CHANNEL_ID, REGISTRATION_CHANNEL_ID, NOTIFICATION_CHANNEL_ID) существуют в указанной гильдии и доступны боту.
4. Проверка, что все роли из конфига (MANAGER_ROLE_IDS, PARTICIPANT_ROLE_ID) существуют в указанной гильдии.
5. Результат проверки — в лог (успех/что именно не прошло), чтобы при рестарте через systemd причина сбоя была видна в journalctl.

===========================================
ЛОГИКА РАБОТЫ — ДОПОЛНИТЕЛЬНЫЕ ТРЕБОВАНИЯ
===========================================
- Бот одно-гильдийный (работает в рамках одной гильдии GUILD_ID), мульти-сервер поддержку не делать.
- Кнопку "Подтвердить" в форме /tournament_join деактивировать сразу после первого нажатия (disable + обновить сообщение), чтобы двойной клик не создавал дублирующую запись.
- В БД на таблице заявок должно быть уникальное ограничение (constraint) на пару (discord_user_id, registration_cycle_id) — это подстрахует проверку "уже зарегистрирован" от гонки при одновременных запросах.
- Статус регистрации (registration=true/false) перепроверять не только при вызове /tournament_join, но и повторно в момент отправки модалки и в момент нажатия кнопки подтверждения — модератор мог выключить регистрацию, пока пользователь ещё не завершил заполнение.
- У кнопки подтверждения — таймаут ожидания (например, стандартные 180 сек Discord View). По истечении кнопка становится неактивной с понятным текстом ("сессия истекла, повторите /tournament_join").
- Роли модератора (MANAGER_ROLE_IDS) и участника (PARTICIPANT_ROLE_ID) проверять по актуальным ролям пользователя на момент каждого взаимодействия (вызов команды, отправка модалки, нажатие кнопки), не кэшировать.
- Известное и осознанно принятое ограничение: если бот перезапустится в промежутке между отправкой модалки и нажатием кнопки подтверждения, незавершённая заявка потеряется (данные ещё не в БД) — это ок, отдельно не обрабатывать.

===========================================
ЭКСПЛУАТАЦИЯ
===========================================
- Slash-команды синхронизировать именно на уровне гильдии (guild-scoped sync) через GUILD_ID, а не глобально — гильдийная синхронизация применяется мгновенно, глобальная может занимать до часа.
- Логировать не только успешные заявки, но и отклонённые попытки (нет нужной роли, регистрация закрыта, повторная подача) — для разбора обращений от участников/модераторов.
- В документации явно указать путь к файлу SQLite-БД и рекомендовать включить его в регулярные бэкапы сервера (единственное хранилище истории заявок).

===========================================
ДЕПЛОЙ
===========================================
- Бот работает как systemd-сервис (systemctl), в фоне, на Linux-сервере.
- Автоматический перезапуск при падении процесса и при перезагрузке сервера (Restart=always, WantedBy=multi-user.target). В документации привести пример unit-файла.
- Проверки из раздела "ПРОВЕРКИ ПРИ ЗАПУСКЕ СЕРВИСА" выполняются при каждом старте/рестарте сервиса.
